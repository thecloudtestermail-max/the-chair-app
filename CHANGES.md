# What changed: unified sign-in, welcome PDFs, and inconsistency fixes

## Sign-in (one form, one endpoint, everyone)
- `POST /api/auth/login`: customers, receptionists, barbers, owners. Email + password. Staff land on their dashboard, customers stay put. Email is case-insensitive.
- `POST /api/auth/register`: customers create an account (name, email, phone, password).
- `POST /api/auth/forgot` / `reset`: emailed link when EmailJS is configured; otherwise the person is told to email `SUPPORT_EMAIL` (default geehyness22@gmail.com). Same reply whether or not the address has an account.
- `POST /api/auth/password`: change your own password (also how staff replace a temporary one).
- `POST /api/admin/login`: the platform super_admin's own door. The public sign-in refuses that account.
- One sign-out (`/api/auth/logout`) ends staff and customer sessions.
- UI: `SignInForm` (sign in / create account / forgot) in the pop-up and on `/login` and `/t/<slug>/login`; `/reset-password`; Account pages (`/account`, `/t/<slug>/account`, dashboard **Account**); forced change-password screen.
- Removed: email-code customer sign-in, the staff "setup code" flow, the `devCode` response field.

## Welcome PDFs (generated by the app)
- Owner: creating a tenant. Receptionist / barber: **Staff → Add**, and **Reissue access**.
- Page 1 = sign-in details (the only page with a password); then a guide for the role; then one QR code per page (sign-in, book online, discover) so each can be printed alone.
- Built with `pdf-lib` + `qrcode` (`src/lib/welcomePdf`). Never stored.
- Staff get a temporary password (7 days) and must choose their own at first sign-in.

## Fixes
- Sign-in code was returned in the API response when email failed.
- Anyone could lock a victim out by failing logins on their email; throttling is now per (email+IP), per IP, per email.
- The public login could authenticate the super_admin.
- Suspended salons' staff sessions kept working for up to 7 days.
- Barbers saw a status control the API refused; they can now confirm/complete/cancel their own bookings.
- New barbers had no linked profile (saw nothing); one is created automatically.
- Loyalty points were displayed but never credited: now 1 per whole dollar on Completed, once per visit.
- Customers now get received / confirmed / cancelled emails (when EmailJS is configured).
- "You're booked" for a Pending booking; booking page prefills a signed-in customer; "Book with Marcus" preselects Marcus.
- Staff had no way back to the dashboard from public pages (Dashboard link).
- PWA manifests used off-brand colours.
- Tests: removed dead flows; fixed broken fake-DB tests, a booking test that could never pass, a test that contradicted its route, and a hard-coded 2026-06-01 date that rotted; fake DB gained `$inc`, `$group`, `deleteMany`, `updateMany`, `cursor.project`, MongoDB-accurate projections and Date equality.

## After deploying
See DEPLOY.md: `npm install`, `npm run db:init`, `npm run db:normalize-emails` (dry run, then `-- --apply`), optional `SUPPORT_EMAIL`. Password resets without email: `npm run db:reset-password`.
